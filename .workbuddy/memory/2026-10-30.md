## 修复：宠物永久站立、不换动作

根因：`src/windows/util/pet/swfPet.js` 的状态机靠 Flash 旧版 JS API 驱动
（`CurrentFrame/TotalFrames/IsPlaying/GotoFrame`），Ruffle 未实现这些方法，
帧号恒为 null，`total == current + lastTimeCut` 永不成立，动作队列全部卡死，
宠物停在 `Enter*.swf` 末帧（站姿）。

改动（仅 `src/windows/util/pet/swfPet.js`，+156/-72）：
- 新增 Ruffle 适配层 `ffIsPlaying/ffTotal/ffCurrent/ffPlay/ffStop/ffGoto/ffPercent`：
  优先 `el.instance` 的 wasm 接口，取不到则用 `el.ruffle(1).metadata`
  的 `numFrames/frameRate` 按播放时长推算帧号（WeakMap per-element 计时）。
- `setState()` 增加 `1 === a` 放行：`Stand.swf` 只有 1 帧，等不到"倒数第 N 帧"。
- 新增 `armIdle()`：每次落回 normal 重新排闲置动作，形成常驻循环；
  原逻辑只在 `nextSwf()` 排一次，演完就不再有动作。
- 闲置气泡:玩耍比例 3:7 → **1:9**（用户要求，`o({0,100}) < 10` 走气泡）；
  闲置间隔 22.5~52.5s → **10~25s**。
- `armIdle()` 增加让位：`this.router?.isSick` 非 0（生病/垂死/死亡）时不自发玩耍；
  打工/学习/旅行按用户要求**不做**让位（原版这三类本就无专门动画，全程站着）。
- `changeSwf()` 用 `bindDom()` 轮询等新节点挂载，替代"90ms 后 getElementById"，
  避免 polyfill 晚到导致 `this.dom` 指向已移除节点。
- `createAnimationFrame` 的重新注册移出 try/catch，回调抛错不再打死整条动画循环。

清理：删除 index.js 的 `_idleTimer` 与 main.js 的 `[idle]` 定时器补丁。
前者守卫写成 `info.pet.hatched`（该字段不存在），从未生效；后者与 armIdle 重复。

实测（electron 探针，已废弃）：`enter → normal → play → etoj → normal → eat`
全链路换片成功，`currentFrame` 正确递增，闲置在 ~60s 触发；用户已手动验证。

## 修复：宠物在屏幕边缘时弹出面板跑到屏幕外

根因：control/rightMenu/stateInfo/tip 只按"相对宠物的偏移"算窗口坐标，
没有任何屏幕边界修正（宠物主窗口本身有 clamp，面板没有）。宠物在右下角时
control（1100×505）右溢 478px、下溢 500px，整块出屏点不到。

改动：
- 新增 `src/windows/util/screen.js`：`getWorkArea(anchor)` 用
  `screen.getDisplayNearestPoint().workArea`（含多屏/任务栏），
  `clampToScreen(x,y,w,h,anchor)` 做边界收敛，面板超屏时退化左上对齐。
- `popups/control/main.js`：新增 `calcPosition()`，下方放不下翻到宠物上方，
  再算 clamp；`cleate()` 与 `setPosition()` 统一走它。
- `popups/rightMenu/main.js`：followMain 偏移后 clamp（按实际尺寸 +10）。
- `popups/stateInfo/main.js`：clamp 后再作为初始 x/y。
- `popups/tip/main.js`：新增 `calcPosition()`，顶部放不下翻到宠物下方 + clamp。
- 注意 `window.js` 创建窗口时会给未声明 `notChangeSize` 的窗口各 +10px，
  rightMenu / tip 的 clamp 用 `this.width + 10 / this.height + 10`。
- store/setup/infoCard/backRoom/fishing/smallGame/windowTip 未指定 x/y（默认居中），无需改。

实测（electron 临时脚本，真实 workArea 0,33,1470,858）：control 右下角由
"完全出屏"变为 [370,247]，四角+中央全在屏内；超大面板退化左上对齐正常。

## 修正：control 面板"跑到屏幕上方"

上一版对 control 做了"下方放不下就翻到宠物上方"，宠物在右下角时 1100×505 的
面板被翻到 y=214，横在老屏幕中上部，顶部菜单图标看起来像"整块面板跑到上面去了"。
改为：下方放不下时不再上翻，直接贴工作区底边（`y = area.y + area.height - height`），
保持"从下方展开"的方向；仍然过一遍 clampToScreen。
右下角实测 → [370,386]，底边 891 正好贴底，四角均不越界。
经验：大面板（接近屏幕尺寸）不要做上下翻转，翻转会造成明显的方向跳变；
只有小窗口（气泡 tip）才适合上/下互换。

## 修正：control 三个菜单按钮（日常/交互/活动）位置不对

窗口位置本身是对的（日志 out/bounds 都是 [370,386]，贴右贴底在屏内），
问题在**按钮相对面板的内容定位**：原设计面板水平居中于宠物、顶边贴宠物脚下，
三个按钮在面板顶部**水平居中** = 宠物脚下正下方。宠物在右下角时 1100 宽面板
放不下被钳制贴右到 x=370，但按钮仍死钉在面板正中央（屏幕 x≈920），
而宠物中心在 x≈1340，按钮比宠物偏左 ~420px，孤零零悬在屏幕中下部。

修法：让按钮**水平锚定到宠物中心**，而非固定在面板中央。
- `control/preload.js`：新增 `control_ToHtml_menuOffset` 通道。
- `control/main.js`：新增 `_sendMenuOffset()`，在 `setPosition()` 和
  `cleate().then()` 里把"宠物中心相对面板左边缘的 x"下发给渲染层。
- `control/index.js`：data 加 `menuCenterX`；computed `activeMenuStyle()` 把它
  换算成 `justify-content:flex-start + paddingLeft`（按钮总宽 170 半宽 85，
  clamp 到 [0, 1100-170=930]）。
- `control/index.html`：`.activeMenu` 去掉 `fjc`，改绑 `:style="activeMenuStyle"`。
实测数值：右下角 petCenter=1340 → 按钮中心=970（屏幕 1340）偏移 0px；
居中/贴左/贴右上四场景均精确对齐。二级菜单 `.m_children` 是相对 `.menu` 定位，
会随按钮一起对齐。

### 修正：上一轮把 `fjc`（display:flex）删掉了，导致只剩"日常"一个按钮
`.activeMenu` 的横排完全依赖 `fjc` 提供的 `display:flex`。移除后三个 `.menu`
（各 `h100`=465px）变成块级竖排，后两个被窗口裁掉 → 界面只剩一个按钮。
**经验：这个项目的横排布局全部靠 `fjc/fcc/fb` 等工具类，不能为了改
`justify-content` 而删掉它们；内联 style 优先级更高，保留 class + 内联覆盖即可。**

### 最终方案：按钮绝对定位到"宠物脚下"
- `_sendMenuOffset(position, maxSize, panelPos)` 改为下发 `{left, top, up}`：
  `left = 宠物中心x - 面板x - 85`，`top = 宠物脚底y - 面板y`，各 clamp 到窗口内；
  `up = 按钮下方剩余屏幕空间 < 220px`（二级菜单展开高度）。
- `index.js`：`menuPos` 对象 + `activeMenuStyle` 返回 `position:absolute; left; top;
  width:auto; height:auto; paddingTop:0; display:flex`。
- `index.html`：恢复 `fjc`，`:class="{ menuUp: menuPos && menuPos.up }"`。
- `index.css`：`.activeMenu.menuUp .m_children { top:auto; bottom:50px }`，
  同时把 `.m_h_name` 挪到按钮下方、`.smallLine` 翻转，避免向上展开时与标签重叠。

为什么必须 `up`：面板被钳制贴底后窗口只到工作区底边，宠物脚下只剩 60~120px，
二级菜单（约 220px）会被 `#appMain{overflow:hidden}` 裁掉。向上展开是唯一可行解，
代价是菜单展开时会盖住企鹅本体（悬浮菜单可接受）。
实测（workArea 0,33,1470,858 / 面板 370,386）：按钮屏坐标 [1295,774]~[1465,824]，
宠物 x1290~1470、脚底 779，完全贴合且不越界；中部/顶部场景 up=false 正常向下展开。

### 三级面板里的浮动提示出窗 / 被裁（用户反馈："你要学习语文吗"、hover 课程提示）
根因：两处提示都是 `position:fixed` + `left/top = 鼠标 + 15px`，没有任何边界处理。
窗口只有 1100x505，面板贴到右下角后鼠标就在窗口右下，提示必然画到窗口外被裁掉
（窗口外的东西浏览器不渲染，看起来就像"被面板限制住"）。

修法（`popups/control/index.js`）：
- 新增 `tipPos(mx,my,w,h)`：默认贴鼠标右下 15px；右侧/下侧放不下就翻到左/上，
  最后 clamp 进窗口并留 8px 边距。
- `.activeTip .tipMain`（300x140 确认框）→ computed `tipMainStyle`，尺寸是常量。
- `.c_m_a_tip`（hover 商品/课程提示）尺寸随内容变，→ `goodTipStyle()` + `measureGoodTip()`：
  每次 mousemove 后量一次当前可见的那条，把真实宽高存 `goodTipSize`；
  未量到前用 180x70 保守估计，保证不越界。
- CSS `.c_m_a_tip` 加 `max-width:220px`、`pointer-events:none`
  （不加 pointer-events 的话鼠标移到提示上会把 :hover 断掉，提示闪烁）。

无头实测（1100x505）：goodTip 72x62、tipMain 300x140；鼠标在 (1080,490)/(20,20)/
(560,250)/(1090,20)/(20,495)/(900,480) 六个位置，两种提示全部落在窗口内。

### 心情来源梳理 + 补「触控板滚动」和「拖拽绕圈」
原有 mood 写入点只有 4 处（main.js / State.js）：
1. `State.useConsumables`：任何消耗品 +100（不只食物/清洁，吃药也加）
2. smallTalk 说完关气泡：`main.js:635` → `tip/main.js:96` `addPetInfo` +5~20
3. 点宠物：`main.js:537` 20% 概率 +5~20，但守卫是 `control.show && t.data.isDown`，
   实际只有 1100x505 主面板已打开时才算
4. "滚轮"：`main.js:581` 20% 概率 +5~20，但 `roller` 是 mousedown 的 `which==2`（鼠标中键）
   发出的，触控板按不出来；真正的 `wheel` 事件全仓没监听 → 等于不可达
减：`GrowUp.getEffectHungerCleanMood` 每心跳 -random(2,4)；mood<600 时 hunger/clean 额外 +2。

本轮补的两条（用户要的）：
- `main/index.js` 新增 `bindWheel()`：window 上监真实 `wheel` 事件（触控板双指滑动也派发），
  800ms 节流（触控板有惯性滚动），发出既有 `{type:"roller"}` 分支复用 +5~20 逻辑。
- `main/index.js` 新增 `checkDragCircle()`：拖拽时用 `screenX/screenY`（clientX 会因窗口移动失真）
  做「连续三点转角累加」= 路径曲率积分。累计 ≥ 0.9 圈判定陪玩，4s 冷却，发 `{type:"circle"}`。
  主进程 `main.js` 新增 circle 分支：mood +random(10,30)（clamp 到 maxInfo.mood）、
  `openSpeak({communication:["toHeartTolk"], nextActiveStr:"play"})`。

算法实测（node 模拟）：画 1 圈累计 0.98 圈、1.2 圈 1.18、2 圈 1.98、r=40 小圈 0.98；
直线 0.00、锯齿 -0.46、原地抖动 0.00、半圈 0.49 —— 只有真绕圈的会触发。
因此门槛取 0.9 而不是 1.2（1.2 时整画一圈都过不了）。
